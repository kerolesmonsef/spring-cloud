Kafka · Week 1 Quick Reference

Kafka notes, from zero

The words learned so far and the commands that go with them. Broker runs in Docker as container kafka on port 9092. Every Kafka tool lives in /opt/kafka/bin/ inside that container.

The words

WordMeaningShop example
Record One message, one piece of news. “order 42 created”
Broker The Kafka server. Stores records safely and hands them out to whoever asks. Docker container kafka, port 9092
Topic A named box inside the broker. Records of the same kind go in the same topic. topic orders holds all order news
Producer Any program that writes records into a topic. Order service writes “order 1 created” into orders
Consumer Any program that reads records from a topic. Reading does not delete. Email service reads orders and sends “thank you” emails
Offset The position number of a record (0, 1, 2…). Never changes, never reused. A bookmark so a consumer knows where it stopped. Email service read up to offset 2 → after restart continues at 3

Topic — create and list

Create topic orders

docker exec -it kafka /opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 --create --topic orders --partitions 3
Created topic orders.

List all topics

docker exec -it kafka /opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 --list
orders

Describe topic orders

docker exec -it kafka /opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 --describe --topic orders

kafka-topics.sh params

Kafka's tool for managing topics. Pick one action: --create, --list or --describe.

ParamDescription
--bootstrap-server localhost:9092Required. Where the broker is (the door number).
--createAction. Make a new topic. Needs --topic.
--listAction. Show the names of all topics.
--describeAction. Show details of a topic: how many partitions, and each one.
--topic ordersWhich topic. Needed by --create; optional for --describe (without it: all topics).
--partitions 3Optional, with --create. Split the topic into 3 pieces (partitions 0, 1, 2).

Producer — send records into a topic

docker exec -it kafka /opt/kafka/bin/kafka-console-producer.sh --bootstrap-server localhost:9092 --topic orders

A > sign appears. Each line + Enter = one record sent. Ctrl+C to quit.

>order 1 created
>order 2 created
>order 3 created

No “saved” message is printed — that is normal. To see the records you need a consumer (next step).

kafka-console-producer.sh params

Ready-made producer: you type, it sends.

ParamDescription
--bootstrap-server localhost:9092Required. Where the broker is.
--topic ordersRequired. Which topic to write into.

Consumer — read records from a topic

docker exec -it kafka /opt/kafka/bin/kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic orders --from-beginning
order 1 created
order 2 created
order 3 created

The cursor then waits for new records. Ctrl+C to quit (may print Processed a total of 3 messages).

Run it again → same 3 lines. Reading does not delete. So Email, Warehouse and Invoice services can all read the same orders.

kafka-console-consumer.sh params

Ready-made consumer: reads records and prints them.

ParamDescription
--bootstrap-server localhost:9092Required. Where the broker is.
--topic ordersRequired. Which topic to read from.
--from-beginningOptional. Start from offset 0. Without it you only see new records sent after the consumer starts. Ignored once a --group already has a bookmark.
--group email-serviceOptional. Give the consumer a name. The broker saves its bookmark under that name, so the next run continues where it stopped.
--formatter-property print.offset=trueOptional. Also print each record's offset (position number).
--formatter-property print.partition=trueOptional. Also print which partition (piece) the record is in.

--formatter-property changes how each record is printed. Repeat it once per setting.

TerminalDo

Offset — the position number of each record

OffsetRecord
0order 1 created
1order 2 created
2order 3 created
3(next record goes here)

Like a line number in a notebook. Kafka gives each new record the next number.

See the offsets

docker exec -it kafka /opt/kafka/bin/kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic orders --from-beginning --formatter-property print.offset=true
Offset:0	order 1 created
Offset:1	order 2 created
Offset:2	order 3 created

Params explained in the consumer params table.

Why it matters (shop)

MomentEmail service
Before lunchReads offsets 0, 1, 2. Remembers “finished offset 2”.
After restartContinues at offset 3. No duplicate email, no skipped order.

Offset is unique only inside ONE partition

Topic orders has 3 pieces (partitions 0, 1, 2). Each piece counts from 0 on its own. So Offset:0 can appear more than once — different piece, different record. Print the piece too:

docker exec -it kafka /opt/kafka/bin/kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic orders --from-beginning --formatter-property print.partition=true --formatter-property print.offset=true
Partition:0	Offset:26	a7a
Partition:0	Offset:27	koko
Partition:2	Offset:0	hola
Partition:2	Offset:1	a7a

Real address of a record = topic + partition + offset, e.g. orders / 2 / 0 = “hola”.

Do not press arrow keys in the producer: they are sent as junk records and can scramble the consumer's screen.

Continue from where it stopped — give the consumer a name

CommandBookmark saved?Starts at
no --group, no --from-beginningNothe end → only new records
no --group, with --from-beginningNooffset 0 — every time
--group email-serviceYes, saved in the brokerfirst run: as asked; later runs: where it stopped
 
docker exec -it kafka /opt/kafka/bin/kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic orders --group email-service --from-beginning --formatter-property print.partition=true --formatter-property print.offset=true

Run 1 → all records. Ctrl+C. Run 2 (same command) → nothing (already read). Send 1 new record → run 3 shows only that one. Once a group has a bookmark, --from-beginning is ignored.

See the saved bookmark

docker exec -it kafka /opt/kafka/bin/kafka-consumer-groups.sh --bootstrap-server localhost:9092 --describe --group email-service

kafka-consumer-groups.sh params

Kafka's tool for looking at named consumers (groups) and their bookmarks.

ParamDescription
--bootstrap-server localhost:9092Required. Where the broker is.
--describeAction. Show the group's bookmark for each partition.
--group email-serviceWhich group (consumer name) to show.

Output columns

ColumnMeaning
CURRENT-OFFSETThe bookmark: next offset this group will read.
LOG-END-OFFSETOffset the next new record will get.
LAGHow many records are not read yet (end − bookmark).
