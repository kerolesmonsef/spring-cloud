Rule of thumb (XSD)

  • Everything used as a request/response/DTO must exist in the .xsd first. XSD = contract. Java classes (wsdl/request/response) mirror it, not the other way round.
  • XSD holds two kinds of tags:
    • xs:complexType — the shape (fields, order). Named = reusable (ref=), anonymous = one-off.
    • xs:element — the nameable tag pluggable into a type.
  • Per CRUD op: 1 request element + 1 response element. Named type only when shape reused (e.g. user).

Types allowed inside XSD

  • Primitives: xs:string xs:long xs:int xs:boolean xs:dateTime xs:date xs:decimal
  • Structure: xs:sequence (ordered), xs:choice, xs:all
  • Cardinality: minOccurs, maxOccurs="unbounded"
  • Validation only (no logic): xs:pattern, xs:minLength, xs:enumeration — not used yet in users.xsd

users.xsd review

  • 1 shared type: user (id, name, email)
  • 5 ops: get / list / create / update / delete — each own request+response
  • createUserRequest has no id (server-assigned)
  • update/deleteResponse → just success: boolean, no object returned
  • listUsersRequest → empty complexType (no fields, just a marker)
