SOAP Review Notes

Quick mind-bookmarks only. Not a tutorial — see todo.md for that.

Rule of thumb (XSD)

  • Everything used as a request/response/DTO must exist in the .xsd first. XSD = contract. Java classes (wsdl/request/response) mirror it, not the other way round.
  • XSD holds two kinds of tags:
    • xs:complexType — the shape (fields, order). Named = reusable (ref=), anonymous = one-off.
    • xs:element — the nameable tag pluggable into a type.
  • Per CRUD op: 1 request element + 1 response element. Named type only when shape reused (e.g. user).

Types allowed inside XSD

  • Primitives: xs:string xs:long xs:int xs:boolean xs:dateTime xs:date xs:decimal
  • Structure: xs:sequence (ordered), xs:choice, xs:all
  • Cardinality: minOccurs, maxOccurs="unbounded"
  • Validation only (no logic): xs:pattern, xs:minLength, xs:enumeration — not used yet in users.xsd

users.xsd review

  • 1 shared type: user (id, name, email)
  • 5 ops: get / list / create / update / delete — each own request+response
  • createUserRequest has no id (server-assigned)
  • update/deleteResponse → just success: boolean, no object returned
  • listUsersRequest → empty complexType (no fields, just a marker)

REST vs SOAP annotation mapping

REST (Spring MVC)SOAP (Spring-WS)Role
@RestController@Endpointrequest handler bean
@RequestMapping/@PostMapping("/path")@PayloadRoot(namespace, localPart)routing (URL+verb vs XML namespace+element name)
@RequestBody@RequestPayloaddeserialize incoming body
@ResponseBody (implicit)@ResponsePayloadserialize return value

REST: many URLs, routed by path+verb. SOAP: one URL (/ws), always POST, routed by which <xxxRequest> element sits inside <soap:Body>.

New SOAP API checklist (with examples from this repo)

  • 1. Contract-first — write XSD before Java. users.xsd: 
    <xs:element name="user" type="tns:user"/>
<xs:complexType name="user">
  <xs:sequence>
    <xs:element name="id" type="xs:long"/>
    <xs:element name="name" type="xs:string"/>
    <xs:element name="email" type="xs:string"/>
  </xs:sequence>
</xs:complexType>
    Named type = reusable (ref="tns:user"). Per op: 1 request + 1 response element.
  • 2. One namespace per domain. Users → http://keroles.com/soapserver/users, Posts → http://keroles.com/soapserver/posts (separate posts.xsd). Stops element-name collisions across domains.
  • 3. Config bean pair per domain (WebServiceConfig.java): 
    @Bean(name = "users")
public DefaultWsdl11Definition defaultWsdl11Definition(XsdSchema usersSchema) {
    DefaultWsdl11Definition d = new DefaultWsdl11Definition();
    d.setPortTypeName("UsersPort");
    d.setLocationUri("/ws");
    d.setTargetNamespace("http://keroles.com/soapserver/users");
    d.setSchema(usersSchema);
    return d;
}
    Bean name "users" → WSDL served at /ws/users.wsdl.
  • 4. Endpoint class, 1:1 op → method (UserEndpoint.java): 
    @PayloadRoot(namespace = NAMESPACE, localPart = "getUserRequest")
@ResponsePayload
public GetUserResponse getUser(@RequestPayload GetUserRequest request) {
    GetUserResponse response = new GetUserResponse();
    userService.findById(request.getId()).ifPresent(user -> response.setUser(toXml(user)));
    return response;
}
    Routing key = XML element name inside <soap:Body>, not URL. PostEndpoint.java mirrors this for posts — template for any new resource.
  • 5. Validation in XSD, not code. Missing in users.xsd — no xs:pattern/minLength. Real API: constrain in the schema itself, e.g. xs:pattern value=".+@.+" on email, so bad input is rejected before it hits endpoint code.
  • 6. SOAP faults. Not present here — getUser with bad id just returns a response with no user set (silent, not prod-grade). Add @SoapFault on a thrown exception, or a SoapFaultMappingExceptionResolver bean, so errors come back as proper SOAP faults.
  • 7. Versioning. Contract change (new required field etc.) → new namespace or new XSD version. Old clients are bound tight to the WSDL they first read.
  • 8. Security. Not present here. WS-Security (Wss4jSecurityInterceptor bean) for signing/encryption, or simpler: HTTPS + basic-auth interceptor in front of /ws/*.
